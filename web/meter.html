SC2 Report Meter

Measures what actually reaches your PC from a Steam Controller 2 (or its Puck): report rate, timing jitter, dropped reports, and how often the gyro data in those reports is really new. Chrome/Edge on desktop (WebHID). Nothing leaves your computer.

not connected

Trigger calibration (SC26RE v15+)

Port of the new Valve step calibration (feature 0xC0). 1) Release both triggers and press Start. 2) Slowly press both triggers fully, hold, then release a few times. 3) Press Save. Steam must be closed (or not holding the controller) for the commands to arrive.

Zero triggers (SC26RE v40+). Fixes triggers that read a little pressed when released (e.g. Steam's desktop mode clicking by itself). Take your fingers off both triggers and press the button: the controller measures the released position for 0.3 s and saves it as 0 % in its calibration (Steam reads it too). Full press is unchanged.

Live settings (SC26RE v42+)

Changed here, applied immediately. Apply = until power-off, Save = kept. “Steam” = follow the value Steam sends (the normal behaviour); setting a number overrides Steam. A hard reset returns everything to defaults. With firmware v44+ this also works while Steam is running (replies meant for Steam are recognised and the request repeated); if something still fails, close Steam.

Gyro at rest: put the controller on a table and press Measure. For 5 s the gyro dead zone and dead bands are switched off (only live, nothing is saved) so the real resting values are seen, then put back. The lowest/highest value per axis, in °/s, is what drift and noise look like on your unit. Use as dead bands copies them, plus the margin, into the X/Y/Z dead band rows above; then press Apply or Save. Keep “Gyro on (standalone)” ticked at the top (otherwise the IMU may be off: all zeros) — calibrate the gyro first for the smallest bands.

Full gyro calibration (v43+, also: hold LB + RB + X + Y for 3 s on the controller — purple LED + chime): put the controller on a table and let go. It measures the gyro at rest for 5 s and sets the pitch/yaw/roll dead bands, calibrates the gyro, measures at rest again, calibrates again and saves — about 15 s. A second chime confirms; touching or moving it just repeats the current step.

Calibrate gyro: put the controller on a table, press, and don't touch it for 2 s (v43+: the gyro is measured while still; if it moved, nothing changes). Zero sticks: hands off both sticks, press; their resting point becomes the centre.

Hard reset to factory settings (SC26RE v40+)

Forgets everything sc26re stored — trigger, stick, trackpad-pressure and gyro calibration, settings sent by Steam, boot chime level, Bluetooth/Puck mode, all Bluetooth and Puck pairings — and reboots the controller. Calibration then comes back from Valve's own storage, the same values the stock firmware uses. Afterwards pair the controller with the Puck or Bluetooth again. Works over USB or the Puck; close Steam first. Same as holding Menu + View + LB + RB for 3 s while switching on.

    How to read it. Stock USB shows ~248 reports/s. The v2 “USB timer” patch should show ~993/s with near-zero drops. Fresh IMU counts new IMU timestamps per second. The firmware refreshes the IMU fields once per FIFO batch (every watermark FIFO words), so this is the batch rate, not the raw sensor rate. With watermark 4 and everything at 480 Hz it reads 480.

    Layout used (Triton state report, ID 0x42, from sc26re): seq @0, IMU timestamp u32 µs @29, accel @33, gyro @39, quaternion @45. If your numbers look nonsensical, pick another report ID from the list. The “IDs seen” line shows every report ID with its length and rate.

    Accel and quaternion all 0? The host has the IMU switched off (Steam enables it only when something uses gyro). Keep Gyro on (standalone) ticked at the top (or Steam’s gyro page open) while measuring. With sc26re the timestamp then falls back to report time, so the IMU numbers are meaningless.
No reports? Some hosts only receive state reports while Steam (or another app) has enabled them. Start Steam, or try a game with Steam Input, then reconnect here. Over wireless, connect the Puck instead; its rate is set by the Puck firmware. Puck + sc26re v3+: the controller builds ~1000 reports/s and the Puck forwards the newest one at each poll, so sequence gaps are reports replaced by newer ones, not losses — the tile then reads “Skipped”.
