SC2 Report Meter

Measures what actually reaches your PC from a Steam Controller 2 (or its Puck): report rate, timing jitter, dropped reports, and how often the gyro data in those reports is really new. Chrome/Edge on desktop (WebHID). Nothing leaves your computer.

Trigger calibration (SC26RE v15+)

Port of the new Valve step calibration (feature 0xC0). 1) Release both triggers and press Start. 2) Slowly press both triggers fully, hold, then release a few times. 3) Press Save. Steam must be closed (or not holding the controller) for the commands to arrive.

    How to read it. Stock USB shows ~248 reports/s. The v2 “USB timer” patch should show ~993/s with near-zero drops. Fresh IMU counts new IMU timestamps per second. The firmware refreshes the IMU fields once per FIFO batch (every watermark FIFO words), so this is the batch rate, not the raw sensor rate. With watermark 4 and everything at 480 Hz it reads 480.

    Layout used (Triton state report, ID 0x42, from sc26re): seq @0, IMU timestamp u32 µs @29, accel @33, gyro @39, quaternion @45. If your numbers look nonsensical, pick another report ID from the list. The “IDs seen” line shows every report ID with its length and rate.

    Accel and quaternion all 0? The host has the IMU switched off (Steam enables it only when something uses gyro). Keep Steam’s Calibration & Advanced Settings → Gyro Calibration page open while measuring. With sc26re the timestamp then falls back to report time, so the IMU numbers are meaningless.
No reports? Some hosts only receive state reports while Steam (or another app) has enabled them. Start Steam, or try a game with Steam Input, then reconnect here. Over wireless, connect the Puck instead; its rate is set by the Puck firmware. Puck + sc26re v3+: the controller builds ~1000 reports/s and the Puck forwards the newest one at each poll, so sequence gaps are reports replaced by newer ones, not losses — the tile then reads “Skipped”.
