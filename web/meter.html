SC2 Report Meter

Measures what actually reaches your PC from a Steam Controller 2 (or its Puck): report rate, timing jitter, dropped reports, and how often the gyro data in those reports is really new. Chrome/Edge on desktop (WebHID). Nothing leaves your computer.

Trigger calibration (SC26RE v15+)

Port of the new Valve step calibration (feature 0xC0). 1) Release both triggers and press Start. 2) Slowly press both triggers fully, hold, then release a few times. 3) Press Save. Steam must be closed (or not holding the controller) for the commands to arrive.

Zero triggers (SC26RE v40+). Fixes triggers that read a little pressed when released (e.g. Steam's desktop mode clicking by itself). Take your fingers off both triggers and press the button: the controller measures the released position for 0.3 s and saves it as 0 % in its calibration (Steam reads it too). Full press is unchanged.

Live settings (SC26RE v42+)

Changed here, applied immediately. Apply = until power-off, Save = kept. “Steam” = follow the value Steam sends (the normal behaviour); setting a number overrides Steam. A hard reset returns everything to defaults. With firmware v44+ this also works while Steam is running (replies meant for Steam are recognised and the request repeated); if something still fails, close Steam.

Gyro at rest: put the controller on a table and press Measure. For 5 s the gyro dead zone and dead bands are switched off (only live, nothing is saved) so the real resting values are seen, then put back. The lowest/highest value per axis, in °/s, is what drift and noise look like on your unit. Use as dead bands copies them, plus the margin, into the X/Y/Z dead band rows above; then press Apply or Save. Keep “Gyro on (standalone)” ticked at the top (otherwise the IMU may be off: all zeros) — calibrate the gyro first for the smallest bands.

LB + RB + X + Y does (v46+): full calibration = the 5-step routine below (drift + pitch/yaw/roll dead bands); drift only (default from v47) = just one drift calibration, same LED and sounds, about 2 s, dead bands left as they are. The meter's “Full gyro calibration (+ dead bands)” button always runs the full routine, so it also sets the gyro dead bands; for drift only use “Calibrate gyro”.

Full gyro calibration (+ dead bands) (v43+; also LB + RB + X + Y held for 3 s when that is set to “full calibration” — purple LED + chime): besides the drift it sets the pitch/yaw/roll dead bands (small movements inside them read 0). Put the controller on a table and let go. It measures the gyro at rest for 5 s and sets the pitch/yaw/roll dead bands, calibrates the gyro, measures at rest again, calibrates again and saves — about 15 s. A second chime confirms; touching or moving it just repeats the current step.

Reset gyro calibration: removes your gyro calibration — the drift goes back to the factory value from Valve's storage and the pitch/yaw/roll dead bands are switched off (saved). Other settings are not touched.

Calibrate gyro: put the controller on a table, press, and don't touch it for 2 s (v43+: the gyro is measured while still; if it moved, nothing changes). Zero sticks: hands off both sticks, press; their resting point becomes the centre.

Gyro as mouse (SC26RE v49+)

The controller turns the gyro into mouse movement itself, like Alpakka, with no built-in dead zone and with fractions of a count carried over (sub-pixel accumulation). Everything else stays a normal Steam controller. Works over cable, Puck and Bluetooth. On/off on the controller: press LB + RB + View together (high beep = on, low = off). It is off after every power-on, and it pauses by itself while a gyro calibration runs. While it is on, no program (Steam included) gets the gyro: the pad report carries no motion data, so the camera is never moved twice (the IMU panel and “Measure at rest” read 0 until you turn it off).

Real world calibration (per game)

Teaches the controller how many mouse counts the game needs for a full 360° turn. In the game, look at something you can find again, then: Start calibration (or LB + RB + View + A on the controller) → press the calibration button to start a slow horizontal turn → press it again when the camera has done exactly 360°. The value is saved. Re-do it per game (or when you change the game's mouse sensitivity). If the turn is too slow or fast, change the speed.

From / to Steam Input (Gyro To Mouse): Steam's “Angles to Mouse Pixels (Dots per 360°)” is the same number as counts per 360° here, and Steam's gyro multiplier (“Natural sensitivity”) is the same as the real world sensitivity here. Both use raw mouse counts, so the values carry over 1:1.

Mouse link test

Checks whether every count the controller sends arrives at the PC (cable vs Puck). Turn the gyro mouse on, press Start, then for 10 s move the controller steadily (keep the activation button held if you use one). The cursor is captured meanwhile; Esc ends early.

Flash firmware (USB cable)

⚠ Close Steam completely before flashing (tray icon → Exit). While Steam is running it talks to the controller at the same time and the flasher will not start.

Flashes a .fw file over the cable, like Ibex Web Utilities, but it keeps your settings: before flashing it saves the controller's sc26re storage (pairings, calibrations, Live settings) and writes it back afterwards. Flashing wipes that storage, which is why Steam asked to pair with the Puck again after every update. Close Steam, connect the controller by cable above, pick the file and press Flash. Chrome / Edge / Brave on desktop (WebHID + Web Serial).

Restore saved settings:

If the controller is still running stock firmware (or sc26re older than v15), there is nothing to save; it flashes anyway. A copy of the saved storage is also downloaded as a file, just in case. If anything goes wrong mid-way the bootloader stays active: run Flash again with the same file (the bootloader port can be selected directly). If the page loses the controller after flashing, press Restore settings (it uses the backup from this session, or pick the downloaded sc26re-settings-backup-….bin); it asks for the controller if needed.

Hard reset to factory settings (SC26RE v40+)

Forgets everything sc26re stored — trigger, stick, trackpad-pressure and gyro calibration, settings sent by Steam, boot chime level, Bluetooth/Puck mode, all Bluetooth and Puck pairings — and reboots the controller. Calibration then comes back from Valve's own storage, the same values the stock firmware uses. Afterwards pair the controller with the Puck or Bluetooth again. Works over USB or the Puck; close Steam first. Same as holding Menu + View + LB + RB for 3 s while switching on.

    How to read it. Stock USB shows ~248 reports/s. The v2 “USB timer” patch should show ~993/s with near-zero drops. Fresh IMU counts new IMU timestamps per second. The firmware refreshes the IMU fields once per FIFO batch (every watermark FIFO words), so this is the batch rate, not the raw sensor rate. With watermark 4 and everything at 480 Hz it reads 480.

    Layout used (Triton state report, ID 0x42, from sc26re): seq @0, IMU timestamp u32 µs @29, accel @33, gyro @39, quaternion @45. If your numbers look nonsensical, pick another report ID from the list. The “IDs seen” line shows every report ID with its length and rate.

    Accel and quaternion all 0? The host has the IMU switched off (Steam enables it only when something uses gyro). Keep Gyro on (standalone) ticked at the top (or Steam’s gyro page open) while measuring. With sc26re the timestamp then falls back to report time, so the IMU numbers are meaningless.
No reports? Some hosts only receive state reports while Steam (or another app) has enabled them. Start Steam, or try a game with Steam Input, then reconnect here. Over wireless, connect the Puck instead; its rate is set by the Puck firmware. Puck + sc26re v3+: the controller builds ~1000 reports/s and the Puck forwards the newest one at each poll, so sequence gaps are reports replaced by newer ones, not losses — the tile then reads “Skipped”.
