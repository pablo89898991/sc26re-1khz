Custom Steam Controller (2026) firmware with **1000 Hz** reports and the 1 kHz IMU path, based on Valve's latest stock firmware **6AE90BC5**.

**Download:** `SC26RE_1k.fw` (`SC26RE_1k_puck_dbg.fw` is the same build with Puck link counters in the quaternion fields). Flash with Ibex Web Utilities or `flash.py`. The report meter is on the [SC2 1 kHz tools](https://pablo89898991.github.io/sc26re-1khz/) page.

## Changes since v39

### Triggers no longer "press themselves" with Steam running
On some controllers the released triggers read slightly pressed and jumped around (about 2000 / 32767) while Steam was running. In Steam's desktop layout RT is the left mouse button and LT the right one, so the mouse froze or behaved as if a button were held. The trigger handling now has three layers of protection.

- **Rest auto-zero.**
  - In the first ~0.3 s after power-on the controller measures where each released trigger rests, and that position is mapped exactly to 0 %.
  - Don't touch the triggers while switching on. If a trigger moves during that window, this step is skipped and the normal calibration is used.
- **Noise filter.** A light ~4 ms low-pass removes the jitter from the 1 kHz single-sample ADC reads.
- **Released dead zone.** The first 8 % of travel reads exactly 0. The rest is stretched, so a full press still reaches 100 %.

### Triggers locked against Steam's corrections
- **Steam's raw trigger modes.** When Steam takes the controller, it switches the triggers to raw mode (`trigger_mode` 1 = mV, 2 = ADC counts) and applies its own calibration math. The firmware now sends the value that corresponds to its own processed result, computed on the same calibration records Steam reads, so Steam ends up with the same value: 0 when released, 100 % when fully pressed.
- **Steam writing calibration records.** Steam's writes of trigger calibration records it keeps on the PC (`cal/trg_l`, `cal/trg_r`) are accepted but ignored, so they can no longer overwrite the controller's calibration with stale values.
- **Still working:** trigger calibration from Steam's wizard and from the report meter, because there the firmware measures the triggers itself.

### "Zero triggers (save)" in the report meter
With both triggers released, press the button. The controller measures the released position and saves it as 0 % in its calibration.
- The full-press end is unchanged.
- The value survives power-off, and Steam reads it too.
- A hard reset undoes it.

### Hard reset to factory settings
**What it forgets:**
- everything sc26re stored: trigger, stick, trackpad-pressure and gyro calibration, settings sent by Steam, boot chime level, Puck/Bluetooth mode;
- **all Puck and Bluetooth pairings**.

**What comes back:** calibration is loaded again from Valve's own storage, the same values the stock firmware uses. Pair the controller again afterwards.

**Three ways to run it:**
- **Report meter:** the "Hard reset to factory settings…" button (USB or Puck; close Steam first).
- **Button chord:** hold **Menu + View + LB + RB** while switching on and keep holding for 3 s.
  - The LED blinks orange while it counts down.
  - Then the LED turns red, a chime plays and the controller reboots.
  - Releasing the buttons early cancels the reset.
- **Serial console:** `settings factory_reset`.

### Forgetting the Puck stays forgotten
v39 made Steam's "forget" work, but after a reboot the firmware could copy the old stock pairing back from Valve's storage. A forgotten pairing is now stored as an empty entry, so it stays forgotten. This also applies to the hard reset.
