Custom Steam Controller (2026) firmware with **1000 Hz** reports and the 1 kHz IMU path, based on Valve's latest stock firmware **6AE90BC5**.

**Download:** `SC26RE_1k.fw`. `SC26RE_1k_puck_dbg.fw` is the same build with Puck link counters in the quaternion fields. Flash it with Ibex Web Utilities or `flash.py`. The report meter and the Puck patcher are on the [SC2 1 kHz tools](https://pablo89898991.github.io/sc26re-1khz/) page.

## Changes since v37

### No more "install an important firmware update" dialog
Steam showed the *"Steam Controller detected! Before you get in-game, let's install an important firmware update"* dialog every time the controller connected. **Do not accept it on sc26re:** it flashes stock firmware over sc26re.

Steam's `controller.txt` log showed the cause. Steam compares what the controller reports with `TRITON_FW_TS` in `Steam/package/hardwareupdater.cfg` (currently `6AE90BC5`). sc26re reported different values from stock firmware:

| | Stock 6AE90BC5 | sc26re ≤ v37 | sc26re v38 |
|---|---|---|---|
| Firmware timestamp, USB | 0x6AE90BC5 | 0xF055xxxx (build number) | **0x6AE90BC5** |
| Firmware timestamp, Puck / Bluetooth | 0x6AE90BC5 | 0x6A3BFE74 (old stock) | **0x6AE90BC5** |
| Hardware ID (HWID) | 72 (from the board) | 69 USB / 73 wireless (fixed) | **from the board, like stock** |

- **Firmware version:** sc26re now reports the stock release it is ported from, `6AE90BC5` with build SHA `1c979e4f05d6`, over every connection. This includes the version attribute and the identity sent to the Puck. The values are set at build time with `CONFIG_IBEX_STOCK_VERSION_TIMESTAMP` and `CONFIG_IBEX_STOCK_VERSION_SHA`.
- **Hardware ID:** read from the board's UICR like stock does (`CUSTOMER[1]` when `CUSTOMER[0]` = `0xac32a429`). If it can't be read, 72 is used.
- **When Valve ships a newer controller firmware,** Steam raises `TRITON_FW_TS` and the dialog comes back until sc26re is ported to it. The daily Valve firmware watcher reports new releases.

### Empty settings answered like stock
- Reading a setting that does not exist, such as an empty Puck pairing slot, now returns an empty answer, like stock. sc26re used to return one zero byte. Steam then logged `Failed to read triton info from controller 0 slot 0` and `Got bond for slot 0 (11)` on every connect.
