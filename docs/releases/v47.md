Custom Steam Controller (2026) firmware with **1000 Hz** reports and the 1 kHz IMU path, based on Valve's latest stock firmware **6AE90BC5**.

**Download:** `SC26RE_1k.fw` is the firmware to use. Also attached:
- `SC26RE_1k_capsense_dbg.fw`: raw stick/grip capsense values in the quaternion fields, for tuning.
- `SC26RE_1k_puck_dbg.fw`: Puck link counters in the quaternion fields.

**How to flash:** use the flasher in the report meter so that your pairings and settings survive (close Steam first, connect by cable, keep "keep settings" ticked). The report meter is on the [SC2 1 kHz tools](https://pablo89898991.github.io/sc26re-1khz/) page; refresh it (Ctrl+F5) after updating.

## Changes since v46

### Gyro and accelerometer: a new sample in every USB report
The IMU path was rebuilt. Over USB, measured with an IMU polling test (new gyro/accel values per second as seen by the PC):

| | v46 | v47 |
|---|---|---|
| Gyro | ~632 Hz, intervals 1–3 ms | **~993 Hz**, 1.007 ± 0.086 ms |
| Accel | ~247 Hz, intervals 3–5 ms | **~997 Hz**, 1.003 ± 0.053 ms |

What changed:
- **Gyro and accelerometer run at 2000 Hz in the sensor** (previously gyro 1000 Hz and accel effectively 250 Hz).
- **Both are read straight from the sensor's output registers in one transfer, once per USB frame**, instead of being collected from the FIFO in batches. Each read finds a sample that is at most 0.5 ms old.
- **The IMU thread sends the report itself**, with the latest buttons, sticks and trackpads. Previously the report waited for the main loop to finish scanning and sometimes missed the PC's next poll.
- **A report only takes a USB frame when it carries a new IMU sample**, so the PC no longer receives the same gyro sample twice. Button changes still go out in the next frame.
- The sensor's own fusion (quaternion and drift estimate) now runs at 30 Hz, so its reads collide less often with the gyro reads. Steam's gyro input uses the raw gyro/accel, which stay at 1000 Hz.

Over the Puck the IMU is read every ~1 ms from a timer; measured ~855 Hz gyro and ~875 Hz accel (the Puck link is the limit there).

### New Live settings
- **Gyro hardware filter (in the sensor):** 0 = off, **1 = lightest (default)** … 8 = strongest. Filtering inside the IMU before the data leaves it. On a resting controller, 1 removes about a third of the noise compared to 0, and 2 a bit more. Higher values add delay.
- **IMU read timing (USB)** and **IMU bus speed:** advanced, for testing. Leave them at 0 and 400.

### LB + RB + X + Y now does "drift only" by default
Holding LB + RB + X + Y for 3 s now runs the quick **drift-only** calibration (about 2 s) and leaves the pitch/yaw/roll dead bands alone. The 5-step full calibration with dead bands is still available: choose it in **Live settings → Tools → "LB + RB + X + Y does"**, or use the meter's **Full gyro calibration (+ dead bands)** button (it is now labelled that way, because besides the drift it also sets the dead bands; **Calibrate gyro** does the drift only). If you had already picked a mode in the meter, your choice is kept.

### Report meter
- New line in **IMU in reports**: how often the controller reads the IMU, how long one read takes, and errors.
- After connecting, the status line shows the controller's uptime and **why it last started** (power on, restart, watchdog). If the firmware crashed, it shows **CRASH** with the thread and address, which helps find bugs.

### Fixes
- **Saving Live settings no longer restarts the controller** (the USB thread's stack was too small) and the values are now kept.
- On a firmware crash the controller now restarts immediately instead of hanging until the watchdog resets it.
