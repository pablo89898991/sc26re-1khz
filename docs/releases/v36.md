Custom Steam Controller (2026) firmware with **1000 Hz** reports and the 1 kHz IMU path, based on Valve's latest stock firmware **6AE90BC5**.

**Download:** `SC26RE_1k.fw`. `SC26RE_1k_puck_dbg.fw` is the same build with Puck link counters in the quaternion fields. Flash it with Ibex Web Utilities or `flash.py`. The report meter and the Puck patcher are on the [SC2 1 kHz tools](https://pablo89898991.github.io/sc26re-1khz/) page.

## Changes since v35

### Startup safeguard (new)
Some flashes ended with the controller stuck and the LED blinking bright white. You then had to unplug it and hold Steam for about 10 s.

The Valve bootloader starts a 5-second watchdog, which resets the controller if the firmware stops responding. sc26re only fed it from its main loop. If a startup step failed, the firmware stopped without feeding the watchdog, so the controller reset every 5 s and the boot LED blinked each time.

- **Watchdog fed during startup.** A slow first start after flashing (moving settings from stock, USB enumeration) can no longer cause a reset loop. Feeding stops after 30 s, so a real hang is still reset.
- **Startup errors no longer stop the firmware.**
  - If a required part (settings, hardware, USB) fails to start, the controller restarts and tries again. After 5 failed tries it powers off quietly instead of blinking forever. The next press of Steam starts fresh.
  - If the radio fails to start, the controller keeps running over USB, and the power button still works.
- **Safe start.** After 3 startups in a row that ended in a hang or crash, the controller starts without the radio. You can still use it over the cable or flash it again.
  - The count resets after 10 s of stable running.
  - Normal power-on and normal reboots (switching between Puck and Bluetooth, reboots requested by Steam) do not add to it.
- **Boot LED brightness.** The boot LED uses Steam's LED brightness setting instead of 100%.

If the white blinking comes from the Valve bootloader itself not starting the new firmware, that happens before sc26re runs. The 10 s Steam hold is still the fix in that case.

### Device name
- **USB product name is now `SC26RE-1kHz`** (was `SC26re Ibex CFW`). Windows shows it for the composite device, the input device and the COM port.
  - Steam identifies the controller by USB IDs (28DE:1302), so detection is unchanged.
  - Some browsers, e.g. Brave, may still list it as an unknown device in the WebHID picker.
